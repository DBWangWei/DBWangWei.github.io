# Publication Page Tag and Venue Filtering Design

## Goal
Add client-side filtering to both publication pages so visitors can:
- filter papers by a selected tag
- filter papers by a selected venue
- combine one tag and one venue with AND logic
- clear the selection to restore all papers

This should work on:
- `docs/intro/publications.md`
- `docs/intro/publications_selected.md`

The feature must be generated by the publications pipeline so future rebuilds preserve it automatically.

## UX

### Filter controls
Each publication page will render a filter panel below the page title with:
- a tag chip group
- a venue chip group
- a clear filters control
- optional result count text

The user chose clickable chips rather than dropdowns.

### Interaction rules
- Clicking a tag chip selects that tag.
- Clicking the selected tag chip again clears the tag selection.
- Clicking a venue chip selects that venue.
- Clicking the selected venue chip again clears the venue selection.
- If both a tag and a venue are selected, only papers matching both remain visible.
- Clicking clear removes both selections and shows all papers.
- Year headings should automatically hide when every paper in that year has been filtered out.

### Progressive enhancement
If JavaScript is unavailable, the full page should still render normally. Filtering is an enhancement, not a requirement for basic reading.

## Technical design

### Where to implement
Implement the feature in the shared publications rendering pipeline rather than editing generated pages manually.

Primary integration point:
- `tools/publications/build_publications.py`

The actual rendering logic should generate the filter UI, per-entry metadata, and inline script for both publication pages.

### Page annotations
Each rendered publication entry should include normalized metadata via HTML data attributes, for example:
- `data-tags="llm db"`
- `data-venue="icde"`
- `data-year="2025"`

Normalization should be stable and internal-only so visible labels can keep their current formatting.

### Filter UI generation
For each page, collect all unique:
- tags from the records rendered on that page
- venues from the records rendered on that page

Generate chip controls from those page-specific values so:
- the selected-publications page shows only filters relevant to that page
- the all-publications page shows filters relevant to the full dataset

### Client-side behavior
Embed a small JavaScript block that:
1. tracks the currently selected tag and venue
2. toggles active chip state
3. evaluates each paper entry against the selected filters
4. hides unmatched entries
5. recalculates visibility of year headers
6. updates clear/reset state and optional result count

Matching semantics:
- no selection: show all
- tag only: match papers containing that tag
- venue only: match papers with that venue
- both: match papers satisfying tag AND venue

## Styling
Extend `docs/stylesheets/publications.css` to style:
- filter panel layout
- clickable filter chips
- active filter states
- clear button
- hidden entries and hidden year headers

The new UI should visually align with the existing publication chip styling and remain responsive on narrow screens.

## Validation
Verify the following on both publication pages:
- filter controls render correctly
- tag filtering works
- venue filtering works
- combined tag + venue filtering uses AND logic
- clear restores the full list
- year headers disappear when all entries in that year are hidden
- layout remains usable on desktop and mobile widths

## Out of scope
- multi-select tags
- multi-select venues
- server-side filtering
- free-text search
- changing publication metadata or bibliography structure
